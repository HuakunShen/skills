# 成本、许可与偏差控制

## 每次审计独立预算

保存 cost-plan.json：run_id、scope_hash、created_at、currency、pricing_checked_at、模型/工具真实 ID、单价/单位/来源 URL、低/基准/高估计、硬上限和许可记录。未知价格写 null/unknown，不写 0；本地计算无 API 账单但有耗时和资源成本。

阶段分开：获取数据、STT、提取输入/输出、搜索/数据调用、复审、报告。订阅包含额度与 API 账单分开，别假定订阅抵扣 API。不能读取账单则实际费用未知。

公式是核算方法，不是价格承诺：

- STT 近似：待转录分钟 × 已核实每分钟等效费率；token 计费时分钟估计不等于账单。
- 文本：输入 token/1e6 × 输入价 + 输出 token/1e6 × 输出价；缓存、推理、工具另计。
- 核验：独立可核验观点数 × 每条搜索数 × 每次搜索价，再加模型费用。
- 预计总额：已确认账单 + 未确认的保守估算 + 在途最大暴露 + 剩余估计。

用已授权或免费代表性样本估计观点密度/检索次数。不能为估算先偷偷做付费 STT。先处理字幕，再对剩余音频报价。批量编排不自动享有任何 Batch API 折扣。

## 许可

展示对象/日期、待转录小时、语言、服务/模型、本地备选、原音频发送目的地、低/基准/高金额、硬上限和未包含项。已有覆盖此任务的许可就保存原话/消息定位直接使用，不重复询问。

区分 estimate_only、approved_budget、explicit_cost_waiver。用户明确“不用在意费用，直接跑”才是费用豁免；记录范围，不取消其他权限或既有硬上限。API key 和代理自行写的 approval 文件不是授权。脚本批准参数只传递已存在的授权。

## 每个单元重新估计

每个 STT 文件、提取批次和核验任务结束后追加 costs.jsonl：cost_event_id/task_id、provider/model、usage、amount_usd 或 null、amount_kind=billed|estimated|unknown、来源、时间及潜在重试费用。未知成功请求记 potential_charge，不填 0。

每项更新剩余/总额，按批次简洁报告；严重偏离立即报告。默认策略：比批准基准增加 **25% 且至少 US$1** 即明显偏差；无论增幅大小，预计超过硬上限都停止新付费工作。阈值可按用户需求配置，并非统计定律。

扩范围、换语言/模型/服务或增加音频时长时重估。超许可范围就等批准；明确费用豁免可继续并报告偏差，但仍服从独立硬上限。已批预算内正常波动不反复打断。

并行前预留各在途任务的保守成本，不让每个 worker 独享总余额；协调者统一汇总，先保守控制并发。每次新审计都重新估算，不沿用另一个创作者的报价。

## 重试与不确定计费

发送后超时/中止/5xx 可能已计费。保存 in_flight/uncertain，凭 request ID 和服务记录恢复。无法查询时重试可能重复付费，需符合原预算并明确记录，必要时获得新许可。不能宣称跨网络 exactly-once。

同一内容哈希+模型+语言+参数+版本成功过就复用。输出损坏先恢复，不自动重复付费；新版本与旧版本并存。STT 示例只核算转录子阶段，整体模型/搜索费用由协调者另记。
