# Multi-Surface App — one core (any stack), seven surfaces

The pattern is mined from `space-lens`, `refyard`, `ssh-tunnel-ui`, `kkterminal`
(all under `~/ExtDev/`): **one core, one closed contract, up to seven thin
surfaces**. Every surface reuses the same contract + client + web-ui; no surface
re-implements domain rules. Frontend framework and backend language vary per
project (web UI in Svelte/React, or GPUI native for Rust desktop-only; JS alone,
JS+Rust executors, or Rust core via napi) —
the shape below stays the same, only the executor/transport cells change.
**Decide the stack first** (`references/tech-stack.md` Q0/Q1/Q2) before scaffolding.

```
packages/contract   ← closed zod schemas: routes + errors + version + events (ONLY source of truth)
packages/<core>     ← domain logic, host-free (no node:*/DOM/tauri/vscode imports); TS, or thin wrapper over Rust core
packages/client     ← typed fetch/SSE client generated BY HAND from contract (no codegen)
packages/host-node  ← JS executor: Hono server (auth REST + SSE + static SPA) + ports/adapters (only present in single-js / dual shapes)
crates/<core>       ← Rust executor or Rust core (only in dual-js-rust / rust-core-napi shapes; trait-injected ports)
packages/web-ui     ← framework UI (Svelte, React, or any framework), host-free, receives a client via props
apps/cli            ← npx entry: serve + open browser, --daemon/--direct flags, esbuild bundle
apps/web            ← static build with flavors: build / build-desktop / build-dsh
apps/tui            ← fullscreen terminal front over the SAME client; uniview/opentui (JS) or ratatui (Rust)
apps/desktop        ← Tauri shell: frontendDist → ../web/build-desktop (JS executor via invoke shim, Rust executor linked, or napi core)
apps/gpui           ← GPUI native desktop INSTEAD of desktop+web (only Rust desktop-only; separate cargo workspace, no web surfaces)
apps/vscode         ← extension spawns CLI/daemon as service, webview reuses web-ui
integrations/dsh    ← DSH plugin: dist/host.js + dist/client.js + cordis.patch.yml
integrations/kunkun ← Kunkun plugin: dist/ + dist/backend.js (node runtime) + manifest
```

> This skill assumes `coding-style`. If it is available, load it first: strict TS,
> `workspace:*`, source-linked internals, zod at every boundary, closed error codes,
> machine-enforced boundaries. This skill adds the multi-surface layer on top.

## The five things to get right before anything else

1. **Contract first, always.** Routes (`method + path` as `as const`), request/response
   schemas, error codes, `version.ts`, SSE event schemas all live in
   `packages/contract`. Server, client, TUI, web-ui import it; nobody re-declares a
   path or a shape. See `references/contract.md`.
2. **Core stays host-free.** Domain rules go in `packages/<core>` with capabilities
   injected as Ports (`FileStore`, `Probe`, `Process`, `Clock`). `apps/*` and
   `packages/host-node` do composition only. A portable package importing `node:*`,
   `vscode`, or `tauri` is a veto.
3. **Host serves API + SPA together.** `packages/host-node` (Hono) exposes the
   contract routes, a token-auth middleware, SSE streams, AND static hosting of
   `apps/web`'s dist. The CLI's `serve` command starts it; the browser just opens it.
   One process, two duties. See `references/architecture.md`.
4. **Web-UI is host-free and injectable.** `packages/web-ui` takes a `client`
   (or a `backend` port) via props/context — never imports the host, never calls
   `fetch` with a hardcoded URL. That is what lets Tauri / VS Code webview / DSH
   client / Kunkun dist reuse the exact same components.
5. **Each surface is a thin adapter (< 300 lines of glue).** If a surface file
   re-implements validation, state machines, or protocol strings, stop — move it
   down into contract/core/client. Surfaces only do: spawn, serve, embed, bridge
   secrets, map host menus. See `references/surfaces.md`.

## Build order (do not skip)

0. Stack decision (`references/tech-stack.md`): answer Q0/Q1/Q2 with the user, record
   `single-js | dual-js-rust | rust-core-napi` + executor/napi function list +
   frontend framework + TUI stack + per-surface transports. Scaffold only the
   backend shape chosen (do not create `crates/` for single-js).
1. `packages/contract` — routes + schemas + errors + version. Add `check-contract`
   test that server routes and client methods cover the table exhaustively.
2. `packages/<core>` — pure logic + state machine + ports. Unit-test without any host.
3. `packages/client` — typed wrapper over `fetch` + `EventSource`, one method per
   route, throwing coded errors from contract.
4. `packages/host-node` — Hono wiring + auth + static SPA + SSE. `apps/server` (if
   any) is a 20-line composition root.
5. `packages/web-ui` — components against an injected client. Preview with mock client.
6. `apps/cli` — `serve`, `open`, `--daemon/--direct`, `--port`, token file. esbuild
   bundle to `dist/cli.mjs`, `bin` entry, publishable to npm for `npx`.
7. `apps/web` — static build; add `build-desktop` and `build-dsh` flavors early
   (base path + API-endpoint differences only).
8. Then, on demand, one thin adapter at a time: `tui` → `desktop` → `vscode` →
   `dsh` → `kunkun`. Never two adapters in one commit.

## Red lines (instant veto in review)

- ❌ A route path or schema literal hand-written in two places (server + client + TUI).
- ❌ Domain logic inside `apps/*` (CLI/TUI/webview/extension host).
- ❌ `packages/web-ui` importing `packages/host-node` (or `node:*`).
- ❌ `throw new Error("...")` on a contract boundary instead of a closed coded error.
- ❌ A surface that cannot run against `--daemon=<url>` (hardcoded localhost/port).
- ❌ Internal packages built to `dist` for in-workspace consumption (source-link them).
- ❌ New surface added before contract + client + host tests are green.
- ❌ Scaffolding `crates/` + napi packaging before the stack decision says it is needed.
- ❌ Decisions (argv building, state transitions, validation) inside an executor
  backend instead of frontend/core — executors execute, they do not decide.
- ❌ Packing all platform napi binaries into one distributable instead of per-platform
  `optionalDependencies`.

## Evidence honesty

Never claim a surface works without running it: `npx <cli> serve` + `curl /api/health`,
`vite build`, `tauri dev` (or `tauri build --debug`), `vsce package`, DSH/Kunkun
dev-load. Report NOT RUN as NOT RUN.
